# Specify (caveman)

Same specify step as software-dev. Acceptance criteria stay precise and complete — terseness never trims a requirement. Only the surrounding prose compresses.

## Voice (CAVE_001)

- Each requirement: one testable statement. No throat-clearing.
- Keep every negation — a "must not" is a requirement, not filler.
- Scope, non-goals, and risks stated plainly, outcome-first.
- The user's stated intent is quoted verbatim, never re-voiced.

## Do

1. Write `spec.md`: purpose, scope, acceptance criteria, non-goals.
2. Criteria are checkable and complete. Caveman voice shortens the connective prose, not the criteria.
3. Flag ambiguity explicitly rather than smoothing it over.

Output: `spec.md` — precise criteria, terse prose.
