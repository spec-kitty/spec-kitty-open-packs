# Digest consumers (issue #194) — research B

## 1. spec-kitty core
- Pin file: spec-kitty/packs/built-in.source.yaml (also packs/internal.source.yaml). Fields: repository, commit (40-hex), subtree (packs/built-in), tree_digest{algorithm: clean-tree-sha256, value, level: built-in}, requires_core, snapshot_sha256 (second, full-tree digest). Current pinned commit a79c36318b7a506ca2ab26d74705c5e3e406004f.
- Algorithm const: src/charter/offering/packs/pack_pin.py:49 TREE_DIGEST_ALGORITHM="clean-tree-sha256"; pack_fetch.py:85-88 rejects any other algorithm.
- Fetch: src/charter/offering/packs/pack_fetch.py (fetch_commit_subtree of ONE subtree at pin.commit, :137-155; cache ${XDG_CACHE_HOME}/spec-kitty/open-packs/<sha>/<subtree>, :178). _digest_ok (:112-123) = symlink-free AND verify_pack_pin => BOTH clean_tree_digest and snapshot_sha256 must equal the pin.
- clean_tree_digest: src/charter/offering/packs/pack_clean_digest.py:104-135. Declared set = pack.yaml + level layout files (built-in: sharded *.graph.yaml at root) + recognised artifact dirs; sorted by relpath; each file LF-normalised; payload = 8B-BE len(relpath)+relpath+8B-BE len(content)+content; hash_content_bytes. Reads level from pack.yaml descriptor.
- snapshot_sha256: charter.offering.packs.pack_manifest.snapshot_sha256 (rglob all installed files; NFR-004).
- Entry points: hatch_build.py:36,61-68 ensure_built_in_tree reads packs/built-in.source.yaml at build; `make sync-packs` (Makefile:15) -> scripts/sync_packs.py; `spec-kitty charter pack vendor --pack built-in --ref <sha>` (src/specify_cli/cli/commands/charter/pack_vendor.py) bumps pin. Docs: docs/development/how-to/sync-packs.md; AGENTS.md:36-60.
- ADR 0048 (charter) :213-217 already states the intended core shape: "one pin per open-packs commit (built-in.source.yaml); make sync-packs fetches built-in and every pack it pulls in, from that commit, and checks each tree's digest."
- Fit of per-member digests: core's model is one pin = one subtree + one digest, so today core fetches ONLY packs/built-in (now a shell) and verifies a digest of the shell; members are not fetched. Per-member digests fit the model (each member subtree is just another "subtree + clean-tree-sha256 + level" tuple), but core needs a pin shape that lists members (or N pin files). Note clean_tree_digest requires a valid pack.yaml and level-specific layout; the shell and members all have pack.yaml so it works per pack.
- MISMATCH today: open-packs packs/built-in.source.yaml uses algorithm spec-kitty-snapshot-sha256 (scripts/ci/built_in_digest.py, "core's algorithm", all files except pack-manifest.yaml, len-prefixed path+size+bytes), whereas core's pin file carries clean-tree-sha256 + a separate snapshot_sha256. The open-packs digest is the snapshot_sha256 analogue, not the tree_digest core verifies as primary.

## 2. spec-kitty-charter (origin/main, fetched)
- NO tree_digest, no pack-level digest field in contracts/packs/schemas/pack-descriptor.schema.json; no `built-in.source` anywhere.
- DOES define pack integrity: contracts/packs/schemas/pack-manifest.schema.json (ADR-0042 "derived manifest", pack-manifest.yaml): constituents[].content_hash and presets[].content_hash = SHA-256 lower hex of bytes after CRLF/lone CR -> LF; manifest_hash = SHA-256 of RFC 8785 canonical JSON of manifest without manifest_hash. Derived fields: whole-pack write recomputes; reader does not check; round-trip gate verifies. Open-packs already ships packs/built-in/pack-manifest.yaml.
- ADR-0065 D9 (docs/adr/0065...:233-236): server-side version-to-digest history (pack_version, revision, registeredAt) in <config-root>/packs/.history/<packId>.json; revision != same version => 409 pack_version_conflict. D10 (:246-247): https_archive source `sha256` must match body (422 pack_source_refused); git source resolved commit returned in registration. These are charter-computed over registered content, not an open-packs-authored field.
- ADR-0048 :213-217: the core pin/digest model (above). No charter-side digest definition.
- ADR-0053: no pin/digest/manifest hits. ADR-0070:37: `openPacksRef` in charter gradle.properties pins the open-packs checkout charter's tests read (a git ref, no digest); charter ships no open-packs content (syncPacks copies only packs/internal and packs/qa).
- So: charter's integrity notion = per-file content_hash + manifest_hash in pack-manifest.yaml (per pack). No tree digest.

## 4. Conclusion
- Real digest consumers: core (hard, verifying) and open-packs CI. Charter does not consume a tree digest.
- Recommended shape (charter-aligned, nothing invented): per-member integrity = the charter's pack-manifest.yaml (content_hash per file + manifest_hash), one per member pack, already a derived, charter-schema'd artifact. For core's pinned-tree check add, per member, a tree digest alongside as provenance only: a small lockfile (e.g. packs/built-in.source.yaml gains a `members:` list of {pack_id/subtree, tree_digest{algorithm, value}}) using the SAME algorithm core verifies (clean-tree-sha256 over the member's declared set, level-aware) so core can adopt with no new algorithm; keep the shell's own digest. Do not add tree_digest to pack.yaml (pack-descriptor schema is charter-owned, additionalProperties closed; a digest inside the tree it hashes is circular).
- Charter contract to follow: contracts/packs/schemas/pack-manifest.schema.json (ADR-0042) for per-file/pack hashes; ADR-0048 for the one-pin-per-commit, digest-per-tree model. If a pack-level digest is wanted in charter terms, manifest_hash is the closest existing field.
- Decision point for the operator: (a) keep open-packs' spec-kitty-snapshot-sha256 (matches core's snapshot_sha256 only) or (b) emit clean-tree-sha256 too, since core verifies BOTH. Core would need change to fetch members; informative only.
