## Design notes

- **Report layout (NFR-002).** The analyze report keeps the carrier first, then fixed sections in this order: findings table, Finalize Validation, Per-WP Readiness, Requirement Quality, Scenario Audit, Clarification Questions, Coverage Summary, Residual Risk, Charter Alignment, Unmapped Tasks, Metrics, Next Actions. Finding-id prefixes are fixed per category (data-model.md).
- **Prompt vs tactic split.** Prompts own: when to run each pass, the severity mapping, report sections and carrier rules. Tactics own: the checklists (what makes a requirement testable; EARS patterns; what makes a WP prompt ready). The analyze prompt also states each check in one line so it stays usable where tactic context is not surfaced.
- **Template deferral (C-002).** `wp-prompt-readiness-review` tells the agent to read the WP prompt template as resolved for the Mission and compare each WP prompt to it; it names no keys or sections. #230 owns the template.
- **Version gate (FR-004).** Analyze runs `spec-kitty --version` first; below 3.1.0a5 it does not run the check. A could-not-run outcome is HIGH and names `spec-kitty CLI >= 3.1.0a5` and the installed version.
