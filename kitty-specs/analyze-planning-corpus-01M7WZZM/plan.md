## Summary

Extend the software-dev `analyze` step prompt so it (1) loads the whole planning corpus from the `check-prerequisites` inventory and `meta.json`, (2) runs a planning-artifact consistency pass (pass H, prefix `X`, normal severity) and (3) runs a product-coherence pass (pass J, prefix `M`, capped at MEDIUM, never blocks) that ends in one mandatory `Recommendation:` line. The check detail lives in two new foundation tactics; the prompt carries the passes, severities, report sections, prefix rows and metrics. The #247 report content is tightened (scenario rows → `S` findings, `Inferred:` placement) and pinned by tests. The cave-dev analyze prompt names the same checks. Prompt-only, read-only (research R-01 … R-07).

## Design

### Analyze prompt changes (fixed order)

1. **Goal** (line 16): name the planning corpus, not "three core artifacts".
2. **Step 1** (lines 38-44): parse `mission_dir`, `artifact_files`, `artifact_dirs`; read `<mission_dir>/meta.json` for `purpose_tldr`, `purpose_context`, `source_description` (state which are absent). Every `artifact_files` / `artifact_dirs` entry whose path the step has not already loaded (spec, plan, tasks, WP prompts), except `feature_dir`, is a planning input; so is `<mission_dir>/occurrence_map.yaml` when present.
3. **Step 2**: add "From every other planning artifact" — headings first (for a directory, its file list then each file's headings), a body section only when a pass H or J check needs it.
4. **Pass G** wording (#247 fold): only missing-edge, surprising-accepted and surprising-rejected scenario rows become `S` findings; `Inferred:` goes at the start of the carrier `summary` and the table Summary cell; `V` findings never carry it.
5. **Pass H — Intent & Planning-Artifact Consistency** (tactic `planning-corpus-consistency`, category `planning-artifact`, prefix `X`): research and plan decisions implemented / explicitly deferred / flagged; data-model entities, invariants, state transitions; contract operations; quickstart scenarios; `occurrence_map.yaml` categories; any other inventory artifact cross-checked for unreflected content; ungrounded behaviour (no trace at all; a WP mapped to no requirement is already a `V`/`W`/`C` defect and is cited). Evidence must sit in a planning artifact or `meta.json`; spec/plan/tasks differences stay with pass F.
6. **Pass J — Product Coherence** (tactic `product-coherence-review`, category `product-coherence`, prefix `M`): seven lenses; every finding `Inferred:`; MEDIUM or LOW only; cites an `X` id rather than duplicating it; reads the MVP slice from the `MVP Scope` note in `tasks.md` (missing → "MVP unclear" finding).
7. **Severity** (step 5): fold the duplicated "untestable" rule into one line; add `X` at normal rules; add "product-coherence findings are MEDIUM or LOW, never higher".
8. **Report** (step 6): prefix table rows `X`/`M`; id ordering "2a, 2b, then passes A-J"; one-defect rule "the earliest step that detects a defect owns it (2a, 2b, A-G, H, J); later steps cite its id"; example category lowercase; `file:Lnn` location form; sections "Intent & Planning-Artifact Consistency" and "Product Coherence" immediately after Scenario Audit and before Clarification Questions; Scenario Audit table gains a `Finding` column (`—` for accepted/rejected) and fixed kind order; Product Coherence ends with `Recommendation: revise spec | revise plan | revise tasks | proceed` (one chosen; never `proceed` while blocked); metrics lines.
9. **Next Actions** (step 8): echo the recommendation line.
10. **Operating principles**: planning artifacts headings-first.

Line budget: +~60 net lines → ≈ 440-460.
