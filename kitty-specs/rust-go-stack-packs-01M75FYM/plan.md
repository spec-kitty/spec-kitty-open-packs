# Implementation Plan: Rust and Go stack packs

**Branch**: `feat/rust-go-packs` (mission target `feat/rust-go-packs`; PR → `main`) | **Date**: 2026-11-11 | **Spec**: [spec.md](spec.md)
**Input**: Mission specification from `kitty-specs/rust-go-stack-packs-01M75FYM/spec.md`

## Summary

Author two opt-in org Charter Packs, `packs/rust` and `packs/go`. Each holds:

- a conventions styleguide;
- a review-checks toolguide with its guide;
- a specialist implementer profile;
- a preset;
- a DRG fragment;
- the pack documents.

All content is Spec Kitty-authored MIT. It is re-authored from the charter-cobol-migrations seed
tables and resolves their contradictions (research.md R-02). `built-in` is untouched. Each pack
depends on #73's `foundation` pack. That dependency and the cross-pack `foundation::` edges are the
last step, done once `foundation` has a pack_id. Until then, the pull request stays local.

## Technical Context

**Language/Version**: Pack content: YAML artifacts (charter pack schemas at charter `fb24052`) and Markdown; tooling in Python 3.12
**Primary Dependencies**: pyyaml 6.0.3, jsonschema 4.26.0 (the validator's), python-ulid (the spec-kitty install) to mint pack_ids
**Storage**: Files under `packs/rust/`, `packs/go/`, `docs/packs/`
**Testing**: The repository gates (`validate-packs.sh`, `check-built-in.sh`, `check_vocabulary.py`, `gen_pack_reference.py --check`, `python3 -m unittest discover -s tests/<suite>`, the docsite build). The charter service check runs in CI only (spec C-006).
**Target Platform**: The charter service (composition and registration) and Spec Kitty consumers that read packs
**Project Type**: Content and packaging (Charter Packs)
**Performance Goals**: N/A (static content)
**Constraints**: spec C-001 to C-006. Principle descriptions are at most 255 characters (charter #474). The toolguide guide layout is H1 = title, no preamble, `## Overview` first, fixed blocks in charter `GuideBlock` order.
**Scale/Scope**: 2 packs × (1 styleguide, 1 toolguide + guide, 1 profile, 1 preset, 1 fragment, 5 documents), plus 2 generated pages and 4 shared-file row edits.

No dependency is added to this repository. The packs *teach* supply-chain checks (`cargo deny`,
`cargo audit`, `govulncheck`) but install nothing, so DIRECTIVE_051 has no dependency decision to
evaluate here.

## Implementation Concern Map

### IC-01 — Rust pack content

- **Purpose**: Real, general-purpose Rust doctrine: conventions, review checks and a specialist profile.
- **Relevant requirements**: FR-001, FR-002, FR-003, FR-004, FR-013, NFR-001, NFR-002
- **Affected surfaces**: `packs/rust/**`
- **Sequencing/depends-on**: none
- **Risks**: Idiom quality, so a Rust-idiom reviewer is on the pre-PR squad. Principle-length cap. Guide block order.

### IC-02 — Go pack content

- **Purpose**: The same as IC-01, for Go.
- **Relevant requirements**: FR-005, FR-006, FR-007, FR-008, FR-013, NFR-001, NFR-002
- **Affected surfaces**: `packs/go/**`
- **Sequencing/depends-on**: none (parallel with IC-01)
- **Risks**: As IC-01. The `goto` and typed-constant guidance must stay general, not port-shaped.

### IC-03 — Catalog, docs and changelog

- **Purpose**: Make the packs discoverable, with generated pages and minimal shared-file rows.
- **Relevant requirements**: FR-010, FR-011, FR-012
- **Affected surfaces**: `README.md`, `packs/README.md`, `docs/packs/{index,catalog-proposal,rust,go}.md`, `CHANGELOG.md`
- **Sequencing/depends-on**: IC-01, IC-02 (the pages are generated from the packs)
- **Risks**: Conflicts with concurrent pull requests (#73) on the same rows. Rebase and regenerate.

### IC-04 — `foundation` dependency wiring

- **Purpose**: Declare `depends_on` foundation and add the qualified cross-pack edges and profile references.
- **Relevant requirements**: FR-009
- **Affected surfaces**: `packs/{rust,go}/pack.yaml`, `drg/fragment.yaml`, `agent_profiles/*`
- **Sequencing/depends-on**: IC-01, IC-02, and #73's `foundation` existing (external blocker)
- **Risks**: `foundation`'s membership may differ from the proposal, so every edge is checked against the landed pack. The generated pages must be regenerated after this change.
